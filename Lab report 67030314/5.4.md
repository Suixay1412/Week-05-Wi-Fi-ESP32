## 3. คำถามท้ายการทดลอง (Post-Lab Questions)

1. เหตุใดกระบวนการ **4-Way Handshake** จึงพิสูจน์ทราบรหัสผ่าน Wi-Fi ได้โดยไม่ต้องส่งรหัสผ่าน (Passphrase) ลอยไปในอากาศเลยแม้แต่แพ็กเกจเดียว?
ตอบ เพราะทั้งสองฝั่งนำ Passphrase ไปแปลงเป็นคีย์แม่แบบ (PMK) ล่วงหน้า แล้วแลกเปลี่ยนเพียงค่าสุ่มผ่านเฟรม EAPOL-Key เพื่อนำมาคำนวณลายเซ็น MIC ยืนยันความถูกต้อง โดยไม่ต้องส่ง Passphrase ผ่านอากาศ

2. อธิบายบทบาทและที่มาของคีย์ **PMK (Pairwise Master Key)** และ **PTK (Pairwise Transient Key)** ว่ามีความสัมพันธ์กันอย่างไรในการเข้ารหัสเฟรมข้อมูล?
ตอบ PMK คือคีย์แม่แบบถาวรที่คำนวณจาก Passphrase และ SSID ส่วน PTK คือคีย์ชั่วคราวที่เกิดจากการนำ PMK ไปผสมกับค่าสุ่มและ MAC Address ของทั้งสองฝั่ง โดย PTK จะถูกนำไปใช้เข้ารหัสและถอดรหัสแพ็กเกจข้อมูลจริงในอากาศ

3. เหตุใดเมื่อเราพิมพ์ Password ผิด (ข้อ 5.4.2) ESP32 จึงยังคงได้รับ Event **`WIFI_EVENT_STA_CONNECTED`** ก่อนที่จะเกิด Event **`WIFI_EVENT_STA_DISCONNECTED`** ตามมาในภายหลัง?
ตอบ เพราะ `WIFI_EVENT_STA_CONNECTED` เกิดขึ้นจากการตกลงเชื่อมต่อระดับ Link Layer (Phase 2–3) ซึ่งเป็นระบบเปิดที่ยังไม่ตรวจรหัสผ่าน แต่เมื่อเข้าสู่ Phase 4 แล้วรหัสผิดทำให้คำนวณ MIC ไม่ตรงกัน AP จึงค่อยส่ง Disconnect Event ตามมา

4. หากเครือข่าย Wi-Fi ไม่มี DHCP Server (ไม่มีการแจก IP อัตโนมัติ) ผลการทดลองในข้อ 5.4.1 จะหยุดอยู่ที่ขั้นตอนใด และจะไม่เกิด Event ใดขึ้น?
ตอบ จะหยุดอยู่ที่สิ้นสุด Phase 4 โดยเชื่อมต่อและตกลงคีย์เข้ารหัสระดับสัญญาณวิทยุสำเร็จแล้ว แต่จะไม่เกิด Event `IP_EVENT_STA_GOT_IP` ขึ้นเนื่องจากไม่ได้รับการจัดสรร IP Address จากระบบเครือข่าย
